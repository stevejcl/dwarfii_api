## Corrections

- DSO capture now explicitly selects shooting mode **2**. The former hard-coded
  mode 8 selects **Sun**, independently confirmed by both live supported-mode
  inventories. A successful frame in mode 8 did not validate a DSO session.
  Explicit non-DSO use requires discovered mode/stacking/camera support plus
  the matching parent parameter catalog; for Sun 8 this is namespace 3.
- Current camera, notification and task-center descriptors add sensor/focus
  metadata, camera HDR/aspect-ratio state, and resolution aspect ratio. The
  generator hash-verifies both provenance layers and stages their effective
  imports together so old relative imports cannot reload obsolete definitions.
- Added read-only `getCameraAndFocusInfo`, module 12 / command 15860. Its camera
  enum is **1 tele, 2 wide, 3 guide**, distinct from camera parameter/catalog
  IDs 0/1. Its focus enum is **1 tele, 2 guide, 3 wide**.
- Decoded packets retain actual envelope versions/device/client identity.
  Session `peerProtocolVersion` records the first known incoming response and
  resets on disconnect. It is diagnostic metadata, not Android capability data:
  WS response 1.8, outbound profile 1.20, and HTTP parameter configuration 2.6
  are different observations and cannot substitute for each other.
- Known major-1 and major-2 envelopes decode against their shared packet schema.
  APK 3.4.3 builds requests with version 2.7 and the actual hardware device ID;
  the default legacy outbound profiles remain unchanged. See the explicit
  current-app profile in `docs/native-schedules.md`.
- `fetchDefaultParamsConfig` performs an explicit GET, preserves lossless numeric
  identifiers, and exposes a typed HTTP capability version without logging the
  rest of the configuration. `getDefaultParamsConfig` remains the URL builder.
- Session consumer exceptions no longer interrupt decoding, connection lifecycle,
  or other listeners. The existing transport error callback receives diagnostics.

The APK's capture request still serializes only filter and force-start; exposure,

## Boundaries

Capture submission is acceptance pending authoritative device progress; no ACK
proves physical completion. The SDK does not start motion, acquire ownership,
continue a warning, or replay capture automatically after reconnection. Factory
EEPROM/calibration writes are not exposed by this update.

Both firmware releases keep the astronomy and schedule descriptors unchanged.
The native schedule builder/submission API is independently covered by
`current_schedule.test.js`; its feature gate uses the HTTP parameter config
version. A DWARF 3 list timeout remains unresolved even in confirmed DSO mode.
No blind native schedule submission or hardware certification follows from
schema compatibility. Physical probes are controlled separately by the root audit.

The root audit subsequently verified a future Mini schedule through the new SDK:
submission, exact queued readback, immediate cancellation and confirmation of
removal, with existing history preserved and control released. DWARF 3 listing
still timed out in confirmed DSO mode with the exact APK 2.7 request profile;
no successful DWARF 3 native scheduling claim is made.
