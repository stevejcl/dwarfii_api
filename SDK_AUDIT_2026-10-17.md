# SDK protocol audit — 2026-10-17

This review used the adjacent DwarfAlpa research, its recovered firmware schemas,
and its DWARFLAB Android 3.4.1 command inventory. Tests are offline; this audit
does not certify successful physical operation on any telescope.

## Corrections

- Current WebSocket liveness uses binary `getDeviceState` probes instead of
  sending text `ping`. Browser WebSocket cannot emit protocol control ping frames;
  text `pong` no longer hides a dead binary protocol connection.
- Capture responses retain `ResAstroShooting` effective exposure, gain,
  resolution, filter, and temperature-threshold fields and optional presence.
- The current command registry exposes native schedule sync, cancel, list,
  get, replace, unlock, lock, and delete commands (module 13, commands
  16100–16103 and 16105–16108), and telephoto mosaic start (3:11031).
- Mosaic progress (15263) preserves panel identity. Canonical notification
  decoding also covers normal/area autofocus, panorama/framing/compression,
  attitude, wide/guide focus position, defog, cooling, and shutdown.
- Float and boolean parameter echoes retain their full uint64 parameter
  identifiers and match the correct pending operation. Float comparison uses
  the actual float32 wire precision; omitted boolean false retains its meaning.
- Direct `CurrentSession` requests reject nonfinite or nonpositive timeouts.
- Fresh Mini and DWARF 3 catalogs prove the parameter camera identifier occupies
  bits 44–47. Canonical and legacy helpers previously read/wrote bits 8–15,
  causing real wide-angle IDs to be mistaken for telephoto controls. Literal
  live wide/shared IDs now anchor regression tests; unknown bits 8–43 are retained.
- Full catalog normalization merges per-camera `shootingTechSettings`, including
  actual stack-count and mosaic-count ranges, and keeps shared camera-15 settings
  separate. Capture validates the advertised count bounds. The HTTP catalog
  helper preserves raw uint64 IDs before JSON decoding.

The canonical source files were left unchanged, preserving their existing
provenance hashes. Generated `dist` runtime and declarations were rebuilt.

## Evidence and remaining boundaries

`DwarfAlpa/docs/apk-analysis/api-inventory.json` binds command numbers.
`src/current_proto/astro.proto`, `notify.proto`, and `shooting_schedule.proto`
provide exact payload fields. The APK request wrapper `WsStartMosaicReq`
serializes horizontal/vertical scale, rotation, filter, and force-start only;
its constructor's exposure/gain/capture-size values are not serialized there.

Native schedule `params` is opaque JSON in the protobuf schema. Adding its
transport surface does not validate application-generated JSON or authorize
blind replacement of conflicts. The device response code remains authoritative,
including schedule errors whose code occupies field 2 or 3 instead of field 1.

The legacy `WebSocketHandler` singleton and global protocol setters remain
compatibility APIs. Fleet callers must use independent `CurrentWebSocketHandler`
instances and device-scoped state. Never replay movement or capture after
reconnection. Current command presence proves schema/API support, not support
for every hardware or firmware version; DWARF 2 still needs physical validation.

No wire request sequence number exists. Timeout quarantine prevents a late reply
from satisfying a retried command on the same connection. Multiple outstanding
requests for one command are rejected. An unsolicited notification and a delayed
duplicate acknowledgement cannot universally be distinguished from a newer
request; workflows must use subsequent device state/progress to establish
physical completion rather than relying on acknowledgements alone.
